# 研究决策链：Text 找回了 ID 漏例，融合为什么没留下更多？

我想检验的是：根据用户已有交互预测下一件商品时，商品文本能否补上 ID 路线漏掉的目标，以及融合是否保留这类补充。当前证据来自 Beauty CPU 代理实验，只适用于这套代理方法和切分；没有训练真实 EnsRec 双路模型。

## 1. 原来的判断：交互越多，ID 行为线索越充分

根据用户的历史交互，ID 路线可以利用商品间的行为转移；商品描述提供了另一类信息。我的原始预测是：历史很短时，ID 可用线索较少，Text 对漏例的补充可能更大。我也提出要直接检查长历史组的 ID 和 Text 表现，不能把这层关系当成理所当然。

这把问题从“Text 单路是否比 ID 强”改成两步：**在 ID 漏掉的目标中，Text 找回多少？融合后又留下多少？** 只比较两路总 Recall 会漏掉第一步；只数 Text 独有命中则回答不了第二步。

## 2. 先确认这个问题能不能被公平比较

最初计划使用 EnsRec 学到的 ID 和 Text 表征，但融合分数只有在两路商品向量行、标签商品 ID、评估事件和候选集都对齐时才可解释。对导出路径和训练检查点的审查发现，真实模型链还未达到这一条件，因此没有把静态审查误写成真实模型结果。审计材料见[导出探针](id-text-export-probe.md)、[集成审计](integration-audit.md)与[配置审计](config-audit.md)。

为了先检查研究问题，实验改用 CPU 代理：训练序列拟合 ID 转移与流行度；商品目录文本拟合 TF-IDF；同一测试事件、同一目标和同一 12,101 件候选商品用于比较。每条查询取最后一件商品为目标、之前最多 19 件作历史，序列商品 ID `i` 映射到目录 ID `i+1`。这建立了统一比较对象，但它不是 EnsRec 学习表征。

ID 与 Text 的分值尺度不同，于是每条查询先将完整候选集内分数转成百分位，再按 `alpha × ID + (1-alpha) × Text` 融合。这个选择也带来一个待检验边界：稀疏 TF-IDF 令许多候选得分同为零，当前用商品 ID 拆分并列项，融合可能受候选 ID 顺序影响。该敏感性对照待补。

## 3. Text 确实更常找回短历史组的 ID 漏例

验证集选择可见历史长度切点 4。测试集短历史组中，ID top-10 漏掉目标的有 6,776 人，Text 找回 296 人，比例为 4.37%；长历史组对应为 370/14,444，即 2.56%。两者相差 **1.81 个百分点**，用户 bootstrap 95% 区间为 **1.25 至 2.35 个百分点**。由于测试记录最短也有 5 个事件，目标之前恰有 4 件可见商品，所以这个测试里的“短组”实际全是长度 4，不是泛指 0–4 件历史。

这与短历史预测方向一致，但分母是各组自己的 ID 漏例。因此结论是“短组的 ID 漏例更常被 Text 命中”，不能直接改写成“短历史本身导致了差异”。按训练频次低、中、高三组再比较后，短组救回率仍分别高 **2.61、2.38、1.21 个百分点**。目标频次分组是测试后诊断，没有用于路由或选择 alpha；ID 分数仍包含训练流行度回退。这说明三个粗粒度频次组的构成不能单独解释差异，但其他混杂尚未排除。

## 4. 等权融合丢掉了大部分 Text 独有命中

测试集上，Text 命中而 ID 未命中的目标共有 666 个；等权融合仅保留 168 个，即 25.2%。看新增和丢失的净数，等权融合在短组新增 211、丢失 154，净增 57；在长组新增 325、丢失 361，净减 36；全体新增 536、丢失 515，净增 21。

所以第一步的互补信号没有自动变成第二步的总体收益。特别是长组的净变化为负，说明仅凭“Text 有独有命中”就采用统一等权融合并不充分。

Recall@10 之外的指标让取舍更清楚：

| 方法 | 全体 NDCG@10 | 全体 Hit@1 |
| --- | ---: | ---: |
| ID | 0.02869 | 1.167%（261/22,363） |
| Text | 0.01540 | 0.022%（5/22,363） |
| 等权融合 | 0.02428 | 0.470%（105/22,363） |
| 全局 `alpha=0.9` | 0.02995 | 0.868%（194/22,363） |

全局融合的 Recall@10 和整体 NDCG@10 高于 ID，但 Hit@1 低于 ID；长历史组的 NDCG@10 也是 0.02750，略低于 ID 的 0.02820。按 Recall@10 选出的权重提高覆盖，却没有提高首位命中；若首位结果更重要，决策会不同。

## 5. 验证调权也没有支持历史长度自适应

初轮分析按事先写下的方案，用验证集选择长度切点和全局权重；这不是预注册。全局 `alpha=0.9`，在本次测试上相对 ID 净增 169 次。它是一次验证集选择后的测试观察，仍需额外数据判断是否稳定。

首轮测试查看后，才追加了按短、长组分别在验证集选权重的探索。两组仍都选出 `alpha=0.9`，路由结果与全局权重完全相同，净变化为 0。它没有证明分组调权有效，也没有用测试标签选权重；其事后探索身份已在[README](../README.md)披露。

负对照把候选侧商品文本向量与商品 ID 的对应关系打乱，Text Recall@10 降至 0.085%，接近随机候选率 0.083%。这支持当前命中依赖正确的商品文本对应，不代表模型已能泛化。

## 6. 更具体的竞争解释：已看过商品占据候选位

Text 先把用户已经看过的商品排在前面，这些商品不能解释一个全新下一商品目标。测试目标在完整既往历史中都没有出现，但短组 Text 前十平均有 **3.672 个位置**被历史商品占据，长组为 **4.637 个**。Text 第一名是历史商品的比例在短组为 **97.18%**，长组为 **91.16%**。候选库保留这些已看过商品，因此它们可能挤占新目标的排名位置；长组占位更多，与长组救回率较低的方向一致。这是事后观察到的潜在机制，不能说它解释了全部差异。

## 7. 下一步：验证候选占位与并列排名的影响

已完成的诊断显示，频次分层后短组差异仍在，精确长度也表明当前短组只对应 4 件历史；但频次粗分无法排除其他构成因素。接下来有两个固定敏感性对照：把同分候选改为平均排名，检查商品 ID tie-break 是否影响 Text 和融合；对所有方法统一排除可见历史商品候选，检查历史商品占位是否改变命中与排名。两项都由验证集各自选择权重，测试集只报告结果。其结果再决定是否做独立切分复核或投入真实 EnsRec 双路训练。细节见[轻量探测计划](lightweight-probe-plan.md)及[补充诊断](beauty-followup-diagnostics.md)。

## 复盘时可追问的五个问题

1. 为什么“ID 漏例中的 Text 命中率”和“融合新增、丢失、净命中”是两个不同问题？
2. 为什么两路必须比较相同事件、目标和候选商品？商品 ID 映射错误会怎样伪造差异？
3. 哪些参数由验证集选择，为什么测试集不能用于选择？首轮测试后追加的探索应怎样表述？
4. 短组与长组分别是什么精确历史长度？ID 漏例中的商品频次会怎样改变组间比较？Text 前十里已看过商品占位，又提出了什么竞争解释？
5. 全局权重让 Recall@10、NDCG@10 和 Hit@1 分别怎样变化？如果首位命中最重要，下一步决策会不会不同？

我提出了短历史互补假设，指认 Text 消融字段错位，并决定先做简单完整的代理案例；方案设计、实验实现和审阅由 AI 辅助完成。
